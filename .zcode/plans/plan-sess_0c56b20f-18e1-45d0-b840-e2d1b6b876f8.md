# Publish `startuper-workflows` — standalone extraction of the video-creator agent system

## Goal

Extract the **development-time agent system** (layer B: `.agents/` + hooks + orchestration scripts) from `~/dev/video-creator` into a fully standalone, MIT-licensed repo at `github.com/t10ko/startuper-workflows` (remote already configured, currently empty). The standalone version works in **Claude Code + ZCode**, lands PRs via **gh CLI (GitHub, t10ko account)**, and contains **no Videobooks-specific content**.

Non-goals: layer A (the LangGraph product pipeline under `src/agents/`), modifying video-creator in any way, two-way sync back to video-creator.

## Key design decisions

1. **Runtime is stdlib-only, invoked with plain `python3`** (not `uv run`): consumers are arbitrary-language repos. Hook commands become `python3 "$CLAUDE_PROJECT_DIR/.claude/hooks/<x>.py"`; each hook/script resolves its own real path (symlink-aware, `Path(__file__).resolve()`) and bootstraps `src/agentic_workflows` onto `sys.path`. Scripts keep anchoring to `git rev-parse --show-toplevel` = the consumer repo.
2. **Install model mirrors the existing projection design**: `install.sh <target-repo>` symlinks `.agents/*` content into the target's `.agents/`, creates `.claude/{commands,skills,agents,rules}` + `.zcode/commands` projections, symlinks hooks into target `.claude/hooks/`, merges hook wiring + permissions into the target's `.claude/settings.json` (idempotent, backs up first), writes target-local `.agents/config.toml` overrides. The repo self-hosts the same way.
3. **PR landing via gh**: landing-and-pr.md rewritten to `gh pr create` / `gh pr view --json state` (resume check); new rule `github-pr-api.md` replaces `bitbucket-pr-api.md` (never merge/decline via API — PR review stays the human checkpoint); drop `src/clients/bitbucket_client.py` and `BITBUCKET_TOKEN`; `gh auth login` documented. The single authorized push form `git push -u origin HEAD:<branch>` and its git_write_guard carve-out stay unchanged.
4. **Project-specific knobs become config-owned** (`.agents/config.toml`, single-source rule preserved): `[project] verify_cmd` (default `make verify`; prose says "the verify command from config"), `[spike] fixture` (no bundled default), `USER_PERSONAS` read-first becomes "if `docs/USER_PERSONAS.md` exists". code-review-fix-loop's `src-ui` npm step becomes conditional on a detected JS/TS package dir.
5. **Vocabulary scrub map**: Videobooks→(removed), chapter/scene-scope→"one independently landable scope at a time", ChapterScopeViolationScanner wave in extract-issues→dropped (noted as extensibility point), Pass1/Pass2 refs→removed, Haiku/Sonnet/Opus→tier language (standard-model implementers, deep-model investigation) with a per-host mapping note, REQ-xxx spec anchors→dropped or re-pointed to the standalone repo's own docs, `docs/specs/2026-07-23-...` history refs→moved into the skill's design-notes.

## Work phases (each ends in a commit)

**Phase 0 — Scaffolding:** LICENSE (MIT, t10ko), .gitignore, pyproject.toml, Makefile, README skeleton, CI workflow. Initial commit.
**Phase 1 — Vendored Python runtime:** copy the ~18 `src/utils/*` modules into `src/agentic_workflows/` (flat, names preserved), strip app-only imports (`src.config`, `src.utils.logger`, style_contract, rag_asset_retriever — replace with stdlib logging/simplifications), add `github_client.py` (thin `gh` wrapper: create_pull_request, get_pull_request_state). Enforce + test stdlib-only.
**Phase 2 — Hooks:** port 9 hook entry scripts into `hooks/` with sys.path bootstrap + `python3` invocation; port `.claude/settings.json` as the self-hosting template (hooks, permissions, response-contract injection; drop `CLAUDE_CODE_AUTO_COMPACT_WINDOW`? keep, it's host-generic; drop ralph-loop plugin entry).
**Phase 3 — Orchestration scripts:** port 12 scripts, rewrite `src.utils.*` → `agentic_workflows.*`, keep exit-code contracts identical.
**Phase 4 — `.agents/` content port + genericization:** workflows, skills (+references), specialists, rules, AGENTS.md (trim multi-harness section to Claude Code + ZCode), config.toml gains `[project]`/`[spike]` sections. Apply the scrub map above; drop product specialists; root-cause-analysis loses the ralph-loop state read.
**Phase 5 — Projections + installer:** self-hosting symlinks in this repo; `install.sh`/`uninstall.sh` (bash, python3-compatible targets); settings-merge logic idempotent + backed up.
**Phase 6 — Tests:** port the applicable projection/policy tests (claude/zcode projection, inventory sync, frontmatter portability ≤1024 chars, skill reference pointers, code-review-fix-loop skill, block-git-mutations hook, plan_run_state, parallel_plan_grouping, rules README inventory, hooks portability) re-pinned to new canonical text; add tests for symlink/sys.path resolution and installer idempotency. `make verify` green.
**Phase 7 — Docs + polish:** full README (what/why, workflow catalog table, install, quickstart, compatibility matrix, architecture diagram, config reference), CONTRIBUTING, secrets/privacy scrub pass (grep for tokens, `ungravity`, bitbucket URLs, personal paths).
**Phase 8 — Publish:** dogfood validation (install into a scratch repo, run smoke: `/commit-message`, a dry-run plan, worktree acquire/release); push `main` to origin; make repo public via `gh repo edit t10ko/startuper-workflows --visibility public`; final report.

## Verification

- `make verify` green in the standalone repo (ruff + full pytest suite).
- Fresh-clone install test into a scratch project: projections resolve, hooks fire under `python3` without uv, `worktree_acquire.py` honors cap N from the scratch repo's config, `gh` smoke (PR create against a throwaway branch on the scratch repo, then close it).
- ZCode side: commands discoverable from `.zcode/commands` symlink; skill frontmatter descriptions ≤1024 chars.

## Notes / risks

- The ported tests pin exact prose phrases; Phase 4 rewording and Phase 6 re-pinning happen together, in one pass per file, to avoid a long red window.
